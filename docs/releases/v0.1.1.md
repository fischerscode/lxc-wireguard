# v0.1.1 — Explicit forwarding-off defaults

Status: prepared locally; not published. Release/tag/push and GitHub Actions
publication require approval. Never replace or overwrite the v0.1.0 assets.

## Fix

- Explicitly disable IPv4 and IPv6 forwarding through
  `/etc/sysctl.d/10-wireguard-defaults.conf`, including defaults for new interfaces.
- Preserve normal OpenRC startup ordering before networking. Operators can enable
  routing through a later sysctl file or an explicitly configured VPN service.
- Add archive regression checks and an isolated Alpine sysctl/ifupdown-ng test.
  No periodic reset, custom runtime service or deployment-specific configuration
  is added.

An operator observed IPv4 forwarding enabled immediately after the first boot of
a fresh v0.1.0 container. The underlying cause is unconfirmed; this patch makes
the intended image defaults explicit.

## Upgrade

New containers must use the new v0.1.1 archive once approved and published.
Existing containers are not updated by template import or `apk upgrade`: review
routing requirements before deploying this file yourself. Disabling forwarding
on an intentionally configured router interrupts traffic. Keep intentional routing
in an operator-owned later file such as `90-wireguard-routing.conf`.

## Validation and publication gate

Local static checks and isolated component tests are recorded in
[the validation report](../validation.md). They do not certify Proxmox boot behavior.
A full production build plus fresh-container/reboot tests of both forwarding values
(0 by default, explicitly enableable by the operator) remain required before
approval. Publish a distinct v0.1.1 tag/release only after that approval; the
existing published-release workflow attaches its new archive and SHA256SUMS.
